Console API

Toutes les commandes de l'API REST de Rempart, exécutables depuis cette page. Choisissez une commande, ajustez les paramètres, cliquez sur Exécuter : la réponse réelle du serveur s'affiche, avec la commande curl équivalente à copier dans vos scripts.

Authentification des requêtes

Vérification…

Les requêtes partent avec le cookie de votre session ouverte dans l'interface. Toutes les commandes sont alors possibles, selon votre rôle. Se connecter si besoin.

Ce sont de vraies commandes.Elles agissent sur ce serveur et sont inscrites dans le journal d'audit signé. Les suppressions demandent un second clic de confirmation.

Démarrage rapide

  1. Obtenir un jeton. Dans l'interface : Sécurité → Accès API. Par script, avec un compte administrateur : POST /api/login, puis POST /api/tokens (exemple ci-dessous, ou scripts/rempart-token.sh).
  2. L'enregistrer dans un fichier en 0600, sous la forme d'un en-tête : Authorization: Bearer rmp_…. Il n'apparaît alors ni dans l'historique du shell ni dans ps.
  3. L'utiliser avec curl -H @fichier. Une requête qui modifie quelque chose avec un jeton n'a pas besoin de l'en-tête X-Rempart.
# 1. Session d'un compte administrateur (local ou LDAP), cookie gardé dans un fichier
curl -sS -c /tmp/rempart.cookies -H 'Content-Type: application/json' \
  --data @/root/rempart-login.json https://rempart.maison.lan:8080/api/login
#    {"username":"admin","password":"…"}  dans rempart-login.json (0600)
#    Si la réponse contient "second_factor": true, envoyez le code :
#    curl -b /tmp/rempart.cookies -c /tmp/rempart.cookies -H 'X-Rempart: 1' \
#      -H 'Content-Type: application/json' --data '{"challenge":"…","code":"123456"}' …/api/login/otp

# 2. Création du jeton (portée admin, 30 jours)
curl -sS -b /tmp/rempart.cookies -H 'X-Rempart: 1' -H 'Content-Type: application/json' \
  --data '{"name":"installation","scopes":["admin"],"days":30}' \
  https://rempart.maison.lan:8080/api/tokens

# 3. Utilisation
printf 'Authorization: Bearer %s\n' 'rmp_…' > /etc/rempart/api.auth && chmod 600 /etc/rempart/api.auth
curl -sS -H @/etc/rempart/api.auth https://rempart.maison.lan:8080/api/status

Portées et rôles

PortéeQui peut l'utiliser

Codes de réponse

200Succès. Le corps est du JSON, sauf mention contraire (texte, archive).
400Requête invalide : JSON mal formé, champ inconnu (refusé), valeur hors bornes. Le motif est dans {"error": "…"}.
401Non authentifié, session expirée, jeton inconnu, expiré ou révoqué.
403Portée ou rôle insuffisant, commande réservée à l'interface, en-tête X-Rempart manquant, adresse hors de web.allowed_admins.
409Conflit : instance réplique (configuration en lecture seule), port déjà pris, opération déjà en cours.
429Trop d'échecs de connexion depuis cette adresse : attendre le délai indiqué.

Aucune commande ne correspond à ce filtre.
